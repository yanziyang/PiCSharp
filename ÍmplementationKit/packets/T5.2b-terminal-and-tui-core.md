## Why this is now delegable

`tui-strategy.md` rates T5.2 **C — not delegable as a single packet**, because `tui.ts` depends on
`terminal-image.ts`, which needs Kitty/iTerm2 protocol work. That rating was assigned without
measuring the dependency. Measured, it is two narrow seams:

```
tui.ts      imports 3 symbols from terminal-image.ts; 1 appears in the body (isImageLine, 3 uses)
terminal.ts imports 0
```

The other seam is native modifier detection, and upstream already defines its own fallback: every
failure path in `native-modifiers.ts` returns `false`. So both seams have a faithful degraded form,
and neither distorts the 48 tests. **That is what makes this a B, not a C.** If either seam turns out
wider than described once you are inside the code, stop and report it — that is a finding about the
strategy document, not just about this packet.

## Hazards

### 1. `isImageLine` is the one thing in the image seam you must not stub

Two of the three symbols degrade harmlessly. This one does not:

```ts
export function isImageLine(line: string): boolean {
	if (line.startsWith(KITTY_PREFIX) || line.startsWith(ITERM2_PREFIX)) return true;
	return line.includes(KITTY_PREFIX) || line.includes(ITERM2_PREFIX);   // <- the fix
}
```

`test/bug-regression-isimageline-startswith-bug.test.ts` records why. The original used only
`startsWith`, and **when the terminal does not support images** it returned false for lines carrying
image escapes, crashing the TUI with `Rendered line exceeds terminal width`.

The stubbed configuration is exactly the no-image-support configuration, so a naive stub reproduces
the original bug rather than avoiding it. Port this function for real — it is six lines — and port
that regression test with it. `KITTY_PREFIX` and `ITERM2_PREFIX` come across as the constants they
are; you do not need any protocol code to define them.

`getCapabilities()` and `setCellDimensions()` are the two that may sit behind the seam. Model the
seam on upstream's own shape:

```
ImageProtocol      = "kitty" | "iterm2" | null   ->  a nullable enum, null meaning none
TerminalCapabilities { images: ImageProtocol; trueColor: bool; hyperlinks: bool }
CellDimensions       { widthPx: int; heightPx: int }
```

Until T5.5 lands, the default implementation reports `images = null`. `tui.ts:744` reads
`if (!getCapabilities().images)`, so that value selects the no-image path, which is a real upstream
path and not an invented one. Do not invent capability detection.

### 2. The native-modifier seam is one boolean at one call site

`terminal.ts` imports `isNativeModifierPressed` from `native-modifiers.ts`, which loads a Node native
addon (`darwin-modifiers.node`, `win32-console-mode.node`). There is no C# equivalent, and you do not
need one, because **upstream returns `false` from every failure path**: unsupported arch, unsupported
platform, failed require, or a throw from the helper. A port that cannot load it lands on upstream's
own documented fallback.

This is the reason the 4 `normalizeNativeShiftEnterInput` cases are portable at all — the function
takes the shift state as a **parameter**:

```ts
normalizeNativeShiftEnterInput(data, shouldDetect, isShiftPressed)
```

Detection happens at the call site (`terminal.ts:343`) and is passed in. So the pure function is
fully testable with no native code, and the seam is a single injected boolean.

`enableWindowsVTInput()` gets the same treatment: a no-op default. Upstream's own comment says the
consequence is that "Shift+Tab won't be distinguishable from Tab" — a degradation, not a failure.

**Do not P/Invoke in this packet.** A real Windows implementation via `GetConsoleMode` /
`GetAsyncKeyState` is a separate decision with its own testing story. Put it behind the seam, note in
the PR that the seam exists, and leave it.

### 3. `IComponent` is currently a two-member subset of upstream's `Component`

`src/Pi.Tui/TuiTypes.cs` defines `Render(int)` and `Invalidate()`. Upstream has four members:

```ts
render(width: number): string[];
handleInput?(data: string): void;      // missing
wantsKeyRelease?: boolean;             // missing
invalidate(): void;
```

The two missing ones are exactly the two optional ones, and both matter here: `tui.ts` dispatches
input through `handleInput` and gates Kitty release events on `wantsKeyRelease` (`isKeyRelease` is
imported from `keys.ts` for that purpose).

Complete the interface, using **default interface implementations** for the optional members — the
same treatment `IAutocompleteProvider` got in T5.6, and for the same reason: an implementor that does
not supply them must still compile. `Container` must keep working unchanged.

Correcting the record: the T5.3a packet asserted `Component.WantsKeyRelease` was "already in
`Pi.Tui`". It was not, and is not. It arrives here.

### 4. `Terminal`'s dimension and state members are getters, not methods

```ts
get columns(): number;  get rows(): number;  get kittyProtocolActive(): boolean;
```

These are C# properties. The rest of the interface is methods. Do not flatten the distinction.

### 5. Kitty negotiation is stateful, buffered, and a third of the terminal suite

Seven of the 21 cases cover it, and the case names say what the hard parts are: negotiation queried
before the `modifyOtherKeys` fallback, non-zero flags versus zero flags, device attributes without
Kitty flags, **normal input forwarded while waiting for a response**, **split confirmations tracked
across reads**, and **buffered CSI-prefix input replayed when it turns out not to be a Kitty
response**. That last one is the one to get right: input withheld during negotiation must be replayed
in order, not dropped.

`setKittyProtocolActive` in `keys.ts` is already ported and already thread-safe from T5.3a. Call it;
do not reimplement the flag.

### 6. `drainInput(maxMs, idleMs)` waits on two timeouts

Port it faithfully, but where a **test** needs to observe asynchronous work, wait on the condition,
not on a fixed interval. See `WaitUntilAsync` in `StdinBufferTests`, which exists because sleep-based
waits there failed intermittently under load.

The one exception is a delay that is itself the behaviour under test — `idleMs`, or an escape-timeout
interval — where the wait *is* the specification. `StdinBufferTests` has one of those, marked in
place. Do not convert those into condition polls.

### 7. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.
