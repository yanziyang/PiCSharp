# T3.4 — Port the OpenAI Responses provider adapter

## Objective

Implement the raw HTTP/SSE OpenAI Responses provider adapter used by OpenAI, OpenRouter,
GitHub Copilot, Azure-compatible gateways, and other Responses-compatible endpoints in the
pinned Pi v0.84.4 reference.

## Required behavior

- POST a streamed Responses request to `<baseUrl>/responses` through `ProviderHttpClient`.
- Translate system/user/assistant/reasoning/function-call/tool-output history into Responses
  input items, preserving replayable message signatures and `call_id|item_id` relationships.
- Translate tools, strict-schema settings, tool choice, prompt-cache fields, reasoning effort,
  service tier, and provider compatibility flags.
- Parse typed Responses SSE events including response creation, output item addition/completion,
  text/refusal/reasoning deltas, function-call argument deltas/completion, completed/incomplete/
  failed responses, usage, response ID, response status, and error events.
- Emit the frozen Pi assistant event stream with correct partial content and terminal semantics.
- Enforce the OpenAI minimum `max_output_tokens` of 16 and preserve OpenAI's cached-token usage
  accounting and service-tier pricing multipliers.
- Honor auth, caller headers, `Fetch`, `OnPayload`, `OnResponse`, cancellation, timeout, retry,
  and response-body error metadata through the shared transport.
- Expose typed Responses-only options without changing the frozen abstraction project.

## Tests

Use a custom deterministic `HttpMessageHandler`; never call a provider. Cover request payload
and compatibility variants, system-role selection, image and tool-output conversion, message and
tool-call ID normalization, reasoning replay, typed SSE streaming, usage/cost, incomplete status,
minimum output tokens, auth, and HTTP error body preservation.

## Known deliberate translations

- The TypeScript implementation uses the OpenAI SDK and shared TypeScript item types; this port
  uses manual JSON/SSE translation through the already-pushed AOT-safe transport.
- Deferred tool search/additional-tools and Copilot dynamic header generation are left to dedicated
  follow-up milestones; ordinary function tools and replay-safe IDs are implemented here.
