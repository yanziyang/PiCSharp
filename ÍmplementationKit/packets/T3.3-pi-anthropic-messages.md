# T3.3 — Port the Anthropic Messages provider adapter

## Objective

Implement the raw HTTP/SSE Anthropic Messages provider adapter for the pinned Pi v0.84.4
reference. This is the second primary provider protocol and is also used by multiple
Anthropic-compatible ecosystem providers.

## Required behavior

- POST an Anthropic-compatible `/v1/messages` request through `ProviderHttpClient`.
- Preserve request authentication semantics: `x-api-key` for API keys, Bearer authorization
  for OAuth-style tokens, and caller/model-owned auth headers.
- Build system, user, assistant, tool-result, tool, cache-control, thinking, tool-choice,
  metadata, and fallback payload fields from the TypeScript implementation.
- Normalize tool-call IDs to Anthropic's `[A-Za-z0-9_-]` and 64-character constraints.
- Stream recognized Anthropic SSE events into the frozen Pi assistant event model, including
  text, thinking, redacted thinking, signature, incremental JSON tool input, usage, raw stop
  reason, response ID/model, refusal/sensitive errors, and message-start/message-stop framing.
- Use `JsonParseUtilities` for complete and partial streamed JSON; do not add an SDK dependency.
- Honor request cancellation, timeout, `Fetch`, `OnPayload`, `OnResponse`, retry, and error-body
  behavior supplied by the shared transport.
- Expose a typed provider-options record/class for Anthropic-only thinking controls without
  changing the frozen abstraction project.

## Tests

Port the deterministic portions of the upstream Anthropic tests into `AnthropicMessagesTests`.
Use a custom `HttpMessageHandler`; never call Anthropic or spend provider tokens. At minimum
cover payload conversion, image handling, cache retention, thinking enable/disable and budget,
tool schemas/IDs, SSE text/thinking/tool events, usage, stop-reason mapping, malformed tool JSON,
missing auth, HTTP error-body preservation, and response model/ID.

## Known deliberate translations

- The TypeScript adapter uses the Anthropic SDK; this port uses `ProviderHttpClient` and manual
  JSON/SSE mapping to preserve Native AOT compatibility.
- `AnthropicStreamOptions` carries adapter-only fields because the shared frozen `StreamOptions`
  intentionally contains only provider-neutral fields. `StreamSimple` maps the shared reasoning
  level into those fields.
- Deferred tool-reference loading and provider-specific OAuth login UX remain separate milestones;
  ordinary tool results and OAuth-style request headers must still work here.
