# T4.3 — Pi protocol server and live-session dispatch

## Scope

Port the provider-independent server package from the pinned TypeScript package. This milestone
owns the listener/byte-connection contract, handshake state machine, framed message dispatch,
command correlation, server snapshots, and live-session attachment/ownership management. Concrete
Unix socket listeners and durable session backends remain separate packets.

The TypeScript source in `reference/pi/` is read-only and is the specification.

## Required behavior

- Accept byte connections in the awaiting-hello, handshaking, ready, closing, and closed stages.
- Enforce the protocol version and handshake timeout; send typed `hello_error` frames before a
  protocol close where possible.
- Decode arbitrary inbound chunks incrementally, dispatch requests after handshake, and return
  correlated success/error responses with safe internal-error messages.
- Maintain monotonic server revisions and broadcast server/session snapshots and progress events.
- Allocate and persist the exact server-assigned session id on create.
- Acquire one live runtime per session, allow multiple attached connections, reject unowned session
  operations, reject conflicting runtime operations, and dispose idle runtimes.
- Disconnect cleanly on transport close/error and never allow an error observer to corrupt server
  state.
- Keep the server library transport-agnostic and free of Node.js dependencies.

## Known C# mapping

- Node `ByteConnection`/`ByteConnectionHandler` map to `IByteConnection` and callback delegates.
- `MaybePromise<T>` maps to `Task<T>`/`ValueTask<T>`.
- `Set`-based connection/session membership maps to ordinal `HashSet<string>` instances.
- Node timers map to cancellable `Task.Delay` operations; no platform-specific listener is added in
  this packet.
