## Hazards

### 1. `AutocompleteProvider` is public extension API — this is the important one

It is not an internal interface. `docs/extension-api.md` commits to mirroring
`ExtensionUIContext.addAutocompleteProvider(factory)`, where:

```ts
export type AutocompleteProviderFactory = (current: AutocompleteProvider) => AutocompleteProvider;
```

Extensions **implement** this interface and wrap the built-in provider. So the shape you choose here
becomes part of the contract that wave 7 has to honour when porting extensions. Mirror it exactly:

- `GetSuggestions(lines, cursorLine, cursorCol, options)` returning **null** when there is nothing to
  suggest — null is meaningful and distinct from an empty item list.
- `ApplyCompletion(...)` returning the new lines *and* the new cursor position together.
- `TriggerCharacters` and `ShouldTriggerFileCompletion` are **optional** members. In C# give them
  default interface implementations rather than making them required — an extension that does not
  supply them must still compile.
- `options.signal` is an `AbortSignal` → `CancellationToken`, per `translation-patterns.md §4`.

`extension-api.md §7` lists `AutocompleteProviderFactory` as untested residual risk. This packet is
the first chance to retire that: if the interface cannot be mirrored cleanly, **say so in the PR** —
that is a finding about D1, not just about this file.

### 2. `SlashCommand.getArgumentCompletions` returns `Awaitable<T>`

```ts
type Awaitable<T> = T | Promise<T>;
getArgumentCompletions?(argumentPrefix: string): Awaitable<AutocompleteItem[] | null>;
```

Upstream lets an implementation return either a value or a promise. C# has no such union. Use
`ValueTask<AutocompleteItem[]?>` — a synchronous implementation returns a completed `ValueTask`
without allocating, which is the closest faithful equivalent. Do not force callers into `Task`.

Note the doubled nullability: the member is optional **and** its result may be null. Those are two
different "no completions" states and `translation-patterns.md §1` applies.

### 3. `commands` is a heterogeneous list

`CombinedAutocompleteProvider` takes `(SlashCommand | AutocompleteItem)[]`. That union is not an
inheritance relationship upstream — the two shapes simply overlap on `name`/`value`. Model it
explicitly rather than forcing a common base class that upstream does not have, and keep the
discrimination logic where upstream keeps it.

### 4. Path completion shells out to `fd`

The constructor takes `fdPath: string | null`. Where upstream spawns `fd`, the port must behave
identically when it is absent — including on Windows, where it usually will be. The 27 upstream cases
are the specification; port the fallback path faithfully rather than assuming `fd` exists.

### 5. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`. A null suggestion set and an empty one
  differ.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.
