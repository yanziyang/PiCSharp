# T5.1 — Pi TUI layout engine and container model

## Scope

Port the provider-independent layout and container surface from the pinned TypeScript TUI package.
This milestone establishes the component contract, stack sizing rules, layout geometry tree, and the
small basic components used by layout tests. Differential frame rendering, terminal I/O, editor
behavior, grapheme/East-Asian width, images, and search remain separate T5 packets.

The TypeScript source in `reference/pi/` is read-only and is the specification.

## Required behavior

- Preserve component invalidation and child ordering semantics.
- Preserve visible-entry filtering and deterministic grow/shrink allocation, including basis,
  minimum, maximum, gap, and alignment behavior.
- Produce a layout tree with parent links, rectangles, clips, child order, and rendered leaf lines.
- Render vertical and horizontal stacks with the same allocation and alignment rules.
- Supply Box, Spacer, Text, and TruncatedText with faithful padding and basic wrapping behavior;
  terminal sequence-aware width is explicitly deferred to T5.4.
- Keep the TUI library free of platform-specific or Node.js dependencies.

## Known C# mapping

- TypeScript `Component` maps to `IComponent`; `Container` remains a class.
- TypeScript `basis: number | "auto"` maps to a nullable integer basis; null means auto.
- The layout cache uses reference identity for components, matching JavaScript object identity.
- Full ANSI/grapheme and East-Asian display-width behavior is not silently approximated in later
  renderer work; it belongs to T5.4 and is called out here as a deliberate boundary.
