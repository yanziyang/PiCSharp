# `T2.2a` — Port Pi AI authentication contracts and in-memory storage

**Wave:** 2  **Delegation fit:** B  **Depends on:** `T2.1a`

## Objective

Port the provider-neutral authentication contracts, default environment context, credential
store, and shared provider-auth resolution rules from the pinned `@earendil-works/pi-ai`
package. This milestone supplies the authentication surface required by the `Models` runtime and
provider adapters without adding persistence or interactive provider implementations.

Do not modify `reference/`, `src/Pi.Ai.Abstractions/`, provider adapters, or application-owned
credential persistence. The existing abstractions project is the dependency boundary; auth types
and runtime behavior belong to `Pi.Ai`.

## Deliberate translations

- TypeScript credential unions and auth events/prompts become closed C# record hierarchies with the
  upstream discriminator strings. Extra OAuth credential fields are retained in a JSON object so
  provider-specific values are not discarded.
- `AbortSignal` becomes `CancellationToken`; cancellation is observable at the same public
  operation boundaries, while queued in-memory mutations continue to drain after a caller stops
  waiting, matching the upstream promise-chain behavior.
- JavaScript's `undefined` optionality maps to nullable properties omitted by normal C# callers;
  explicit JSON persistence is deferred to the file-backed auth task.
- The TypeScript `ProviderEnv` and `ProviderHeaders` aliases use the existing
  `ProviderEnvironment` and `ProviderHeaders` collections from `Pi.Ai.Abstractions`.

## Oracle and acceptance

- Port the non-network auth, credential serialization-shape, cancellation, double-checked OAuth
  refresh, and error-wrapping cases into `AuthTests.cs`.
- Never execute a provider API, shell command, or interactive login in these tests.
- Build with zero warnings, run the full test executable suite, and pass format verification.
- Preserve upstream error codes/messages and record any CLR-vs-JavaScript semantic difference in
  the implementation summary.
