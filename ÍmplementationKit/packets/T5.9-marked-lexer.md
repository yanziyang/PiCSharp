# `T5.9` — Port the marked lexer and pi's parser configuration

**Wave:** 5 (`Pi.Tui`)  **Delegation fit:** B
**Depends on:** nothing new. `reference/marked/` is vendored and pinned; `Pi.Tui` exists.
**Plan reference:** first of two packets for `components/markdown.ts` (1,015 LOC, 81 cases). `T5.10`,
the renderer, follows once this oracle passes.
**Status:** Ready for dispatch, 2026-09-13.

---

## Objective

Port the marked 18.0.5 lexer to `src/Pi.Tui/Marked/`, and pi's parser configuration from `markdown.ts`
to `src/Pi.Tui/Components/MarkdownParser.cs`. Prove both token for token against the real marked through
a recorded oracle.

## Why

`markdown.ts` renders straight from marked's token stream, so the token stream is the contract. `T5.8`
compared Markdig against it and returned a GO. A follow-up then found renderer-visible divergences
outside that spike's inputs:
- emphasis extras corrupting `x^2 + y^2`;
- autolinked `tel:`;
- different strikethrough pairing;
- differently split table cells.

None of the 81 upstream cases would have caught any of them. The decision and evidence are in
`docs/spikes/markdig-divergence.md` and `tools/spikes/markdig/probes-2026-09-13/`.

A port makes **every token difference a defect against a real oracle**. The upstream renderer tests
cannot check this layer: they assert rendered lines, never tokens.

Pi's parser configuration belongs here, not in the renderer packet, for the same reason. The strict
strikethrough override and the LaTeX tokenizer extensions are regex-heavy lexer code. A JavaScript
versus .NET `\s` difference in `STRICT_STRIKETHROUGH_REGEX` would pass all 81 renderer cases; only this
oracle sees it.

**Parity is already arranged.** `tools/test-parity.sh` excludes `*/Marked/*` from pi-tui's

**`InternalsVisibleTo` is new to this repository, and justified here.** Upstream's `markdownParser`,

## Oracle — build it first

### Recorder

`tools/marked-oracle/` is Node and dev-only; it is never needed to build or test. It must:

1. Install `marked` into a scratch directory, never under `reference/`. Check the version and integrity
   against `reference/marked/PINNED`, and refuse to record on a mismatch.
2. Lex the corpus in three configurations and record `JSON.stringify(tokens)` for every case. Record
   `tokens.links` separately: it is a property on the array, so `JSON.stringify` drops it. A case that
   throws records its message.
3. Start each fixture file with a header: marked version, integrity, configuration name, corpus hash and
   Node version.

| Configuration | What | Why |
|---|---|---|
| `plain` | `new Marked()` | marked's default GFM path, and what `coding-agent`'s `mermaid.ts` uses |
| `pi` | `markdown.ts` from `const STRICT_STRIKETHROUGH_REGEX` to `markdownParser.use({ extensions: [...LATEX_MARKDOWN_EXTENSIONS] })`, extracted from `reference/pi` at record time and type-stripped with `stripTypeScriptTypes` from `node:module` | the exact production parser, with no hand copy to drift |
| `probe` | a small synthetic setup, defined identically in the recorder and in the C# tests | extension mechanics that `pi` does not exercise |

The `pi` extraction was proven on 2026-09-13 with Node 24.18. The recorder must fail loudly if either
marker string is missing.

`probe` must cover at least:
- **Two extensions at one level with overlapping `start` positions.** `use()` puts later extensions
  first (`unshift`, `Instance.ts:113`) but appends their `start` functions.
- **An extension tokenizer that uses its context:** it calls `this.lexer.inlineTokens` and reads its
  `tokens` argument.
- **A `start` function that returns a negative number,** which the lexer ignores.
- **A block-level method override** that falls back to the base method.

### Corpus

All of it lives in `tests/fixtures/marked/`:

- **The spike cases.** The 109 cases in `tools/spikes/markdig/inputs.json`: 94 harvested from
  `markdown.test.ts` and 15 earlier probes.
- **The probe inputs** in `tools/spikes/markdig/probes-2026-09-13/`: `marked/edge-inputs.json`,
  `marked/emphasis-extras-inputs.json`, and the strict-pairing and table-shape inputs in
  `strictprobe/Program.cs` and `tableprobe/Program.cs`.
- **A seeded generated set** covering:
  - **Blocks:**
    - nested blockquotes and lists: ordered and unordered, `.` and `)`, tabs, loose and tight, task items;
    - fences inside lists and quotes, and unclosed fences;
    - indented code, setext and ATX headings, `hr`;
    - HTML blocks and inline tags;
    - link reference definitions, including one directly after a paragraph and a duplicate tag.
  - **Tables:** alignment, escaped pipes, pipes inside code spans, ragged rows.
  - **Inline:**
    - `*`, `_` and `~` delimiter runs of lengths 1 to 4, beside punctuation, whitespace, CJK and emoji;
    - code spans;
    - inline, reference, collapsed and shortcut links and images;
    - `<...>` autolinks, and bare `www.`, `http(s)://` and email URLs with trailing punctuation;
    - entities;
    - every backslash-escaped ASCII punctuation character;
    - hard breaks.
  - **Line endings and special characters:** `\r\n` and lone `\r`; U+2028, U+2029, U+0085, U+00A0
    and U+FEFF beside delimiters.
  - **LaTeX:** the `$`, `$$`, `\(` and `\[` forms, both closed and pending.
- **Streaming prefixes.** pi re-lexes a growing message on every streamed update, so partial Markdown is
  what production actually lexes. Include prefix sweeps of several multi-construct documents: every
  character for short ones, a stride for longer ones.
- **One document of about 50 KB,** concatenated from the corpus, so that offsets deep into a document
  are covered.

**Format.**
- Do not vendor CommonMark or GFM spec examples: they are CC-BY-SA, and this repository is MIT.
- Keep the committed fixtures under 10 MB, and report the size.
- Use JSON Lines in a stable order, split on `\n` only (`JSON.stringify` leaves U+2028 and U+2029
  unescaped).

**The corpus may grow after the oracle commit but never shrink.** No input may be removed or edited to
make the port pass.

### Coverage report

Required in the PR, for each configuration: every token `type` produced, and a hit count for each of the
24 tokenizer methods.

Count in C# with a subclass that overrides every method and delegates to the base; that also proves all
24 can be overridden. A method with zero hits gets corpus inputs, or is named with the reason it cannot
be reached.

## Known hazards

### 1. JavaScript regex semantics

Follow `docs/translation-patterns.md §15`, which was written for this packet, and amend it wherever the
port proves a rule missing. Translate the final patterns in `composed-rules.gfm.json`, not the `edit()`
fragments. `rules.ts`'s `other` patterns are not composed; translate those from the source.

Most likely to bite:
- **`\p{P}\p{S}` classes under the `u` flag** in the emphasis and strikethrough delimiter rules
  (`rules.ts:282-291`). .NET never matches an astral character there, and emoji are `\p{So}`.
- **`\s`, `$` and `.`**, which are everywhere.
- **`listItemRegex` and the `cachedIndentRegex` builders** (`rules.ts:93-99`). They are parameterised by
  bullet or indent, so they cannot be `[GeneratedRegex]`, and any cache must be thread-safe.

A pattern that cannot be expressed in .NET is a stop-and-report, not a workaround.

### 2. Do not copy the remaining source per token

Upstream passes `src`, the unconsumed remainder, to every tokenizer method and extension function, and
re-slices it after each token. V8 does that in constant time; .NET copies.

Measured on 2026-09-13, the copies alone take 46 ms at 100 KB and **8,081 ms at 1 MB**: ten times the
input, 175 times the time. pi renders assistant messages, user messages, skill invocations and summaries
through `Markdown`, and re-lexes on every streamed update. A literal port would stall the UI on long
content.

**So in C#, tokenizer methods and extension `start` and `tokenizer` functions receive a read-only view
over the original string at an offset, not a copied `string`.** The view must support what upstream and
`markdown.ts` do with `src`:
- length and indexing;
- `StartsWith` and `IndexOf`, relative to the view;
- slicing without copying;
- regex matching through `Regex.Match(input, beginning, length)`, which behaves exactly like matching a
  substring (§15), with indices reported relative to the view;
- explicit materialisation when a token field needs a `string`.

The entry points still take `string`: `Marked.Lexer`, `Lexer.Lex`, `Lexer.BlockTokens` and
`Lexer.InlineTokens`. pi's override calls `this.lexer.inlineTokens(text)` on a captured string.

This is a deliberate API decision: a string-typed override surface cannot be linear. Name the view
clearly, document it in §15, and state its shape in the PR, because `T5.10` builds on it. The masking in
`inlineTokens` and the slicing inside `emStrong` and `del` have the same problem within a paragraph.

**Measure it.** In Release, after warm-up, time the median of five runs on three documents:
- 100 KB concatenated from the corpus;
- 1 MB concatenated from the corpus;
- a single 200 KB paragraph with no blank lines.

Report all three; do not assert timings in tests. **1 MB may take at most 15 times as long as 100 KB**;
the copy loop measured 175 times.

### 3. Masking in `inlineTokens`

Before tokenizing inline content, `Lexer.ts:303-336` builds `maskedSrc`: reference links, escaped
punctuation and block-skip spans are overwritten with placeholders of equal length. `emStrong` and `del`
then find delimiters in the mask but take text from `src`, lining the two up by remaining length.

Keep offsets aligned, and run each masking loop over the text as already masked by the loops before it.
`emStrongMask` belongs to hooks, which are not ported.

### 4. Token model

Mirror `marked.d.ts`: `Token`, `Tokens.*` and `TokensList` with `Links`, following
`translation-patterns.md §1` and `§2`. Nested types in a static `Tokens` class are fine: public nested
types such as `Terminal.cs:133` already build under the current analyzers.

- **Tokens are mutable reference types.** The lexer edits tokens after creating them:
  - it merges paragraph and text `raw` and `text`;
  - it fills child `tokens` lists later from its inline queue, so list identity matters;
  - it sets list `loose`;
  - it inserts `checkbox` tokens (`Tokenizer.ts:419-450`).

  `markdown.ts` also edits `token.text` in `trimPartialClosingFences`. `§11` records tokens as a
  deliberate exception to records by default.
- **Absent, `null` and empty are different, and so are their keys.**
  - `list.start` is a number or `""`.
  - `link.title` is absent (autolinks and bare URLs), `null`, or a string; `image.title` is `null` or a
    string.
  - `code.lang` may be absent, and `codeBlockStyle` appears only on indented code.
  - `list_item.checked` appears only on task items.
  - Inline `text` carries `escaped`; block `text` carries `tokens`.
  - Block `html` carries `pre` and `block: true`; inline `html` carries `inLink`, `inRawBlock` and
    `block: false`.
  - A `def` token is emitted only when it is not merged into a preceding paragraph and its tag is new
    (`Lexer.ts:206-222`).
  - Table `align` entries and cell `align` can be `null`.

  The fixtures are the arbiter: compare exact key sets and value types.
- **Extension tokens carry arbitrary properties;** pi's `LatexToken` has an optional `pending`. Support
  them without reflection, since AOT is on. Build comparison JSON with a hand-written writer in the tests.

### 5. Extension surface

- `Tokenizer` is public and not sealed, with `public virtual` methods. A subclass can reach the active
  lexer, the rules and the options, as upstream's `this.lexer`, `this.rules` and `this.options`.
- `TokenizerExtension` has `Name`, `Level`, an optional `Start` returning `int?`, and a `Tokenizer` that
  returns `null` when nothing matches. Both functions receive the active lexer, as upstream's
  `this: TokenizerThis`.
- Inside `Marked`, the `Lexer` method hides the `Lexer` type. Qualify the type there.

### 6. A shared tokenizer on .NET threads

The `Lexer` constructor stores the lexer on the tokenizer, and `BlockTokens` and `InlineTokens` store it
again on entry (`Lexer.ts:31, 108, 304`). With `setOptions({ tokenizer })`, one tokenizer instance serves
every call.

`markdown.ts` keeps a single module-level parser for every `Markdown` component. That is safe in Node;
in .NET, two threads race on `tokenizer.lexer`. This is the third Node single-thread assumption found in
this port, after the TERMUX environment race and the render/input race fixed in `9142ca5`.

- **Concurrent lexing on one `Marked` instance must produce oracle-identical tokens.** Prove it with
  explicit threads: `Pi.Tui.Tests` runs with `ParallelMode.None`, so xUnit will not race it for you.
- **Prefer binding the active lexer per thread.** Do not clone the tokenizer per lexer: that loses state
  a subclass keeps in fields, which upstream shares. A lock is acceptable only with a stated reason in the
  PR.
- **Do not mutate shared options at lex time,** as upstream's `options.tokenizer ||= new Tokenizer()`
  does.
- Configuration through `use` and `setOptions` need not be thread-safe; say so in a doc comment.

### 7. Recursion depth

Blockquotes and lists recurse through `BlockTokens`. A .NET stack overflow ends the process, where V8
throws a catchable `RangeError`.

- Call `RuntimeHelpers.EnsureSufficientExecutionStack()` on the recursive paths.
- Keep nesting in the corpus moderate.
- Add a robustness test at 10,000 levels of blockquotes and of lists that asserts the process survives,
  with either tokens or a catchable exception.
- Report where the limit falls.

### 8. Options and errors

- **Supported:** `gfm: true`, `pedantic: false`, `breaks: false`, `silent: false`, `async: false`,
  `tokenizer` and `extensions`.
- **Any other flag value** throws `NotSupportedException` naming the option.
- **Not exposed at all:** hooks, renderer, `walkTokens`, `childTokens`, renderer extensions, and the
  object form of `tokenizer` in `use()`.
- **Error messages stay verbatim** (`§9`): `Infinite loop on byte: <n>`, `extension name required`, and
  `extension level must be 'block' or 'inline'`.
- **Exception types follow Pi.Tui.** `Pi.Tui` has no `PiException`: that type lives in `Pi.Protocol`,
  which `Pi.Tui` does not reference and must not start referencing. Use BCL exceptions
  (`InvalidOperationException`, `ArgumentException`), as the rest of `Pi.Tui` does.
- **Line endings:** `lex()` normalises `\r\n` and `\r` to `\n` before anything else.

### 9. Native AOT and licence

- Use `[GeneratedRegex]` for fixed patterns and no reflection. Do not use `RegexOptions.Compiled` or
  `NonBacktracking` (§15).
- A generator that emits the translated patterns is welcome, provided it is committed with its output and
  the build uses only the output.
- Copy `reference/marked/LICENSE` to `src/Pi.Tui/Marked/LICENSE`. Each ported file's header names
  marked 18.0.5 and points to it.

### 10. Standing rules

- **Tests come from the oracle, never from reading the C#.** `R4` found nine divergences precisely
  because its expectations came from outside the implementation.
- **Where this packet contradicts the source, the source wins,** and the PR says so.
