# T3.6 — Port Mistral Conversations

## Objective

Port the pinned `@earendil-works/pi-ai` Mistral Conversations adapter to the native Mistral
Chat Completions-compatible endpoint. Preserve the Mistral-specific wire names, nine-character
tool-call identifiers, prompt caching affinity, reasoning modes, streamed content unions, and
provider error formatting without introducing a Node.js dependency.

## Required behavior

- Expose Mistral provider options for tool choice, `promptMode`, and `reasoningEffort`; map
  provider-neutral simple reasoning to the model-specific mode or effort exactly as upstream.
- Emit the native Mistral wire payload: `max_tokens`, `tool_calls`, `tool_call_id`, `tool_choice`,
  `prompt_mode`, `reasoning_effort`, `prompt_cache_key`, and the function-tool schema.
- Normalize historical tool-call IDs to unique nine-character alphanumeric values and apply the
  same mapping to following tool results, including deterministic collision handling.
- Preserve image and non-vision placeholder behavior, text/thinking content chunks, error prefixes,
  empty tool output handling, and assistant `prefix: false`.
- Parse UTF-8 SSE streams with `[DONE]`, streamed string/structured content, streamed tool-call
  fragments, partial JSON repair, response IDs, usage/cache tokens, raw finish reasons, and
  terminal event ordering.
- Use the shared HTTP transport and callbacks, bearer authentication, `x-affinity` prompt-cache
  routing, timeout/cancellation, and Mistral's exact status/body error format.
- Never call a real provider in tests; use a capturing `HttpMessageHandler`.
