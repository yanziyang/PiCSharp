## Why this is next, and why it is a B

T5.2b and T5.2c stubbed the image seam and deferred seven cases to this packet. **T5.5 is now the
keystone of what is left in wave 5**: both remaining large files depend on it.

```
markdown.test.ts        81 cases   needs terminal-image
tui-alt-screen.test.ts  45 cases   needs terminal-image + components/image + 5 more components
```

`tui-strategy.md` rates T5.5 **C**, for "Kitty and iTerm protocols, sizing, GIF/JPEG/PNG probing".
Measured, that rating does not hold — the same way T5.2's did not:

- **`terminal-image.ts` has zero local imports.** It is self-contained, 700 LOC.
- **Probing is header parsing, not decoding.** `getPngDimensions` reads the base64 into a buffer,
  checks the magic bytes `89 50 4E 47`, and does `readUInt32BE(16)`. No image library is involved,
  in TypeScript or in C#.
- **Encoding is deterministic string building.** `renderImage` checks capabilities, computes a cell
  size, and emits an escape sequence per protocol.
- **64 upstream cases specify all of it.**

There is no decoding, no format library, and nothing platform-specific except one `tmux` probe that
already has a precedent in this repository — see hazard 3. **Do not add a NuGet dependency**; if you
believe one is needed, stop and report it, because that would contradict this rating and is worth
knowing.

## Hazards

### 1. The seam already exists and has live consumers — fill it, do not redesign it

`src/Pi.Tui/Images/TerminalImageSeam.cs` defines `ITerminalImageSeam` with five members, and
`NoImageTerminalImageSeam` implements them by reporting no image protocol. `TuiMainScreen` takes one
as a constructor parameter and 596 tests run against the no-image implementation today.

Add the real implementation **beside** the existing one, and keep `ITerminalImageSeam`'s shape. If
the interface genuinely cannot express the real behaviour, that is a finding about T5.2b's seam
design — **report it in the PR** rather than reshaping the interface quietly.

**The default must stay conservative.** A `TuiMainScreen` constructed without an explicit seam must
still behave as it does now unless capabilities actually detect image support. Anything else changes
the behaviour of tests that are not about images.

### 2. The seven skipped cases must be implemented, not merely un-skipped

`tests/Pi.Tui.Tests/TuiRenderImageTests.cs` holds seven `[Fact(..., Skip = ...)]` stubs with
**empty bodies** and upstream's names. They were written in T5.2b so the debt would be counted rather
than invisible. Removing the `Skip` without writing the bodies would turn seven real cases into seven
passing no-ops — the worst possible outcome, because the gate would go green.

Port them from `reference/pi/packages/tui/test/tui-render.test.ts`. They construct a real `Image`,
call `setCapabilities({ images: "kitty", ... })` and `setCellDimensions(...)`, and assert row
reservation, image-id deletion and placement geometry against `TuiMainScreen`. The bookkeeping side
(`parseKittyImageHeader`, `extractKittyImageIds`, `extractKittyImageRows`) already exists in
`MainScreen/` from T5.2c — call it, do not duplicate it.

**`.skip-budget` goes to 0 in this packet**, and `.skip-budget.md`'s table empties. That is the first
time in the project; say so in the PR.

### 3. Four Node APIs, each with a direct C# equivalent

```
execSync("tmux display-message ...", { timeout: 250 })  ->  Process, with a real timeout
homedir()                                               ->  Environment.GetFolderPath(UserProfile)
isAbsolute(p)                                           ->  Path.IsPathRooted / Path.IsPathFullyQualified
pathToFileURL(p)                                        ->  new Uri(p).AbsoluteUri
```

The `tmux` probe shells out to decide whether hyperlinks survive tmux, and **upstream falls back to
`false` on any error**. T5.6 has the precedent: it shells out to `fd`, and the tests cover both the
present and absent cases by building a fake executable. Do the same here — the probe must work when
`tmux` is missing, which on Windows it will be.

**The 250 ms timeout is not decoration.** A probe that blocks the render thread is worse than a probe
that fails. Honour it.

### 4. Byte parsing must be exact, and C# has the right primitives for it

`readUInt32BE(16)` is a big-endian read at a byte offset. Use `BinaryPrimitives.ReadUInt32BigEndian`
over a `ReadOnlySpan<byte>` from `Convert.FromBase64String` — not manual shifts, and not
`BitConverter`, whose endianness follows the platform and will silently be wrong.

Every probe returns **null** for a buffer that is too short or has the wrong magic bytes. Null is a
real result meaning "not this format", distinct from dimensions of zero. `translation-patterns.md §1`.

### 5. Capability caching must not become a racing global

`getCapabilities()` caches, and `setCapabilities` / `resetCapabilitiesCache` exist so tests can force
a value. Upstream keeps that state in module scope — a process-global.

`Pi.Tui.Tests` already runs serially because of two process-global environment variables, and the
reason is written in `TestAssembly.cs`. **Do not add a third.** Keep capability state on the seam
instance, which is what the current interface already implies. Do not remove that attribute either.

### 6. Standing rules

- Where a test must observe asynchronous work, wait on the **condition** —
  `MemoryTerminal.WaitForRenderAsync` or `WaitForConditionAsync`. A delay that is itself the
  behaviour under test is the exception and should carry a comment saying so, as
  `EditorAutocompleteTests` does.
- **`undefined` is not `null`** — `translation-patterns.md §1`.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.
