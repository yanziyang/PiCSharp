# T4.1 — Pi agent loop and stateful Agent runtime

## Scope

Port the provider-independent runtime from the pinned TypeScript agent package. This milestone
owns only the low-level agent loop, tool preparation/execution, lifecycle events, and the stateful
`Agent` wrapper. Session persistence, compaction, harness tools, and the coding-agent extension host
are separate milestones.

The TypeScript source in `reference/pi/` is read-only and is the specification.

Do not edit `reference/`, foundation projects, or any other target path. The C# runtime uses the
existing `Pi.Ai` message and assistant-stream contracts. C# does not have TypeScript declaration
merging, so this first milestone accepts the standard Pi message union; custom coding-agent
messages will be added at the extension-host boundary.

## Required behavior

- Emit the exact agent/turn/message/tool lifecycle order used by the TypeScript loop.
- Support prompt runs and continuation runs; continuation must not re-emit the existing tail.
- Stream partial assistant messages into the mutable loop context and emit updates in order.
- Resolve a dynamic API key before each provider call and pass the active cancellation token.
- Support sequential execution, default parallel execution, and per-tool sequential overrides.
- Prepare arguments before validation; expose the validated mutable object to `beforeToolCall` without
  re-validating mutations, matching the TypeScript behavior.
- Report missing tools, validation failures, blocked calls, thrown tool failures, and aborted calls
  as error tool results rather than terminating a normal loop.
- Ignore progress callbacks after an individual tool execution settles, while awaiting progress
  events raised before settlement.
- Run `afterToolCall`, apply field-level overrides, and implement batch termination only when every
  finalized tool result has `terminate=true`.
- Never execute tool calls from an assistant response stopped for `length`; emit the prescribed
  truncation result and allow the model to retry.
- Support steering messages, follow-up messages, `shouldStopAfterTurn`, and
  `prepareNextTurn` snapshots.
- `Agent` must await subscribers, keep `isStreaming` true until `agent_end` listeners settle, expose
  queue and abort controls, and reject concurrent prompt/continue/reset calls with the upstream text.

## Known C# mapping

- `AgentMessage` is represented by the existing `Pi.Ai.Message` base type in this milestone; custom
  message records are intentionally deferred to the extension host.
- TypeBox validation is represented by the local JSON-Schema validator/coercer in
  `ToolArguments.cs`; no new NuGet dependency is permitted.
- TypeScript `AbortSignal` maps to `CancellationToken`.
