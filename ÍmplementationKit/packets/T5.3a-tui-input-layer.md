## Hazards

### 1. `KeyId` is a TypeScript template-literal type

```ts
export type KeyId = BaseKey | ModifiedKeyId<BaseKey>;
// generates "escape" | "ctrl+a" | "ctrl+shift+p" | …
```

C# cannot express this. Follow `docs/translation-patterns.md §2.2`: **port the key set as data and
validate at runtime.** A `KeyId` becomes a validated string — parse it into modifiers plus a base key,
reject anything unrecognised, and test the rejection. Do not model it as an enum: the modifier
combinations are open-ended and upstream treats these as strings on the wire.

`Key.ctrl("c")`, `Key.ctrlShift("p")` and friends are runtime helpers and port directly.

### 2. `matchesKey` is public extension API

Extensions call it directly — `modal-editor.ts` and `overlay-qa-tests.ts` both do
`matchesKey(data, "escape")`. It is therefore part of the contract `extension-api.md` commits to
mirroring, not an internal helper. Keep the name, the argument order, and the string form of `KeyId`.

### 3. Kitty protocol state is global and mutable

`setKittyProtocolActive` / `isKittyProtocolActive` are module-level mutable state in upstream, and
parsing behaviour depends on them. A direct port gives you a mutable static in C#.

Port the behaviour faithfully, but make the state explicitly thread-safe — the renderer and the input
reader run on different threads in .NET, which was not true of upstream's event loop. Say in the PR
how you did it. Do not silently change *when* the flag is read.

### 4. Escape-sequence parsing must be byte-exact

`keys.ts` supports both legacy sequences and the Kitty keyboard protocol, with 296 references to
escape handling. The 60 upstream cases are the specification for both. Port all of them, names
preserved verbatim — a key that parses to the wrong identifier produces a wrong action with no error
anywhere.

Note `isKeyRelease` and `isKeyRepeat`: the Kitty protocol distinguishes press, repeat and release, and
`Component.WantsKeyRelease` (already in `Pi.Tui`) exists to gate that. Keep the distinction.

### 5. Bracketed paste is stateful across reads

`stdin-buffer.ts` accumulates into `pasteBuffer` until it sees `BRACKETED_PASTE_END`, which may arrive
several reads later, and a paste boundary can split mid-sequence. Upstream is an `EventEmitter`; in C#
use events or a `Channel`, but preserve the buffering semantics exactly. The 59 upstream cases cover
the split cases — they are the reason this file has more tests than its size suggests.

### 6. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.
