## Why this one, and not markdown

`components/markdown.ts` looked like the obvious next packet — 1,015 LOC, 81 cases, unblocked by
T5.5. It is not delegable yet, for a reason worth recording:

```ts
import { Marked, type Token, Tokenizer, type TokenizerExtension, type Tokens } from "marked";

class StrictStrikethroughTokenizer extends Tokenizer { ... }
const LATEX_MARKDOWN_EXTENSIONS: readonly TokenizerExtension[] = [ ... ];
const markdownParser = new Marked({ tokenizer: new StrictStrikethroughTokenizer(), ... });
```

`markdown.ts` does not merely *call* a Markdown parser — it **subclasses `marked`'s `Tokenizer`** and
registers custom tokenizer extensions.

**Correction:** an earlier version of this packet called that an open decision. It is not.
`docs/dependencies.md §3` already approves **Markdig** (BSD-2-Clause) to replace `marked` for
`Pi.Tui` and `Pi.CodingAgent`, and `Directory.Packages.props` has it queued with the note to add the
`PackageVersion` when the consuming wave starts. The approval carried one condition — *"must support
the transformer hook `registerMarkdownTransformer` needs"* — and that condition is satisfied:
`MarkdownTransformer = (markdown: string, context) => string` operates on **source text**, upstream
of parsing, so it needs nothing from the parser at all.

What markdown still needs is a *spike*, not a decision: `StrictStrikethroughTokenizer.del()` and the
inline/block LaTeX tokens must be re-expressed in Markdig's extension model, and marked 18.0.5 and
Markdig may diverge on CommonMark edge cases. The 81 cases assert rendered output — 89 viewport
assertions, zero on the token model — so they are a real oracle for that divergence.

`markdown.ts` also imports `renderLatex` from `latex.ts` and references it 20 times. So **this packet
is on markdown's critical path regardless of how that decision goes**, and it is clean in a way
markdown is not.

## Hazards

### 1. Nineteen cases for 1,380 lines means the suite under-specifies it

That ratio is the point of this hazard. The cases are broad — "renders common symbols, roots, sums,
and integrals" is one case covering many symbols — so the coverage is better than 19 suggests, but
1,380 lines of branching over LaTeX commands, environments and delimiters is not specified by 19
assertions.

Port all 19 first, names verbatim. **Then add coverage for what upstream leaves untested**, the way
`R3` did for `proxy.ts`: read the implementation, identify the branches, and cover them. State in the
PR which behaviours you covered beyond upstream and which you judged not worth covering.

The R3 caveat applies exactly: **do not test the implementation back to itself.** A test written by
reading your own C# and asserting what it currently does certifies whatever bug is in it. Derive the
expectation from `latex.ts`, and where the TypeScript is genuinely ambiguous, say so rather than
guessing.

### 2. `renderLatex` returns `string | undefined`, and two cases exist to prove it

```
returns undefined for unsupported commands
returns undefined for malformed groups and environments
```

`undefined` here means "this is not renderable" and is distinct from an empty string, which would
mean "renders to nothing". In C# this is `string?` returning **null**; `translation-patterns.md §1`.
Returning `""` for the unsupported case would pass a careless test and be wrong.

### 3. It is a pure function — keep it one

No state, no caching, no I/O, no environment reads. If you find yourself adding a static field or a
memo cache, stop and report it: `Pi.Tui.Tests` already runs serially because of two process globals
(the reason is in `TestAssembly.cs`), and this file has no business adding a third.

### 4. Width belongs to `visibleWidth`, which is already ported

`latex.ts` imports exactly one thing, and it is `visibleWidth` — used to align matrix columns and
stack fractions. T5.4 ported it with 99 tests behind it. **Call it.** Do not write a second width
calculation: alignment that disagrees with the rest of the TUI about how wide a character is will be
wrong in precisely the CJK and combining-mark cases that are hardest to notice.

### 5. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`, and hazard 2 is a live instance.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.

## One standing instruction

**The tests ship in the same PR as the code**, and **anything not delivered must be named in the PR.**
The last two packets have been clean on this: T5.3b delivered all 191 cases with names matching
upstream, and T5.5 implemented seven stubs it could have merely un-skipped. This packet's equivalent
temptation is the second objective — porting 19 cases is the easy half, and the added branch coverage
is the half that makes 1,380 lines trustworthy. `T5.4` once dropped its second objective silently and
it had to be re-issued as `R2`; that is the failure mode here.
