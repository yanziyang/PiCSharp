## Hazards

### 1. `Editor` is subclassed by extensions, and C# will not forgive a missing `virtual`

**This is the most consequential decision in the packet.** `docs/extension-api.md` **Amendment D**
commits to editor-replacing extensions *subclassing* rather than implementing an interface:

```ts
class ModalEditor extends CustomEditor { ... }        // CustomEditor extends Editor
ctx.ui.setEditorComponent((tui, theme, kb) => new ModalEditor(tui, theme, kb));
```

In TypeScript every method is overridable and `super.foo()` always works. **In C# a method that is
not `virtual` can never be overridden, and there is no warning at the point where it matters** — the
extension simply cannot be written. Getting this wrong is not a bug to fix later; it silently
forecloses the extension model that D1 committed to.

Three bundled extensions do this today, and they pin the minimum surface:

| Extension | Overrides | Calls |
|---|---|---|
| `modal-editor.ts` | `handleInput(data)` | `super.handleInput(data)`, repeatedly |
| `rainbow-editor.ts` | `handleInput(data)`, `render(width)` | `super.handleInput`, `super.render(width)` |
| `border-status-editor.ts` | `render(width)` | `super.render(width)`, then decorates the lines |
| `CustomEditor` itself | `handleInput(data)` | `super.handleInput`, and `super(tui, theme, options)` |

So, at minimum:

- `Editor` is **public and not sealed** — `extension-api.md §Amendment D` says so explicitly.
- `Render(int width)`, `HandleInput(string data)` and `Invalidate()` are **`virtual`**.
- The constructor is accessible to a subclass and keeps upstream's shape,
  `(TUI tui, EditorTheme theme, EditorOptions? options)`.
- Anything a subclass reads to make its decisions — the text accessors — is `public` or `protected`,
  not private.

**Ship a test that proves it.** Define a subclass in the test project that overrides `Render` and
`HandleInput`, calls `base.` on both, and assert the composition works. T5.6 did exactly this for the
autocomplete factory, and that test is what let `AutocompleteProviderFactory` be retired from the
residual-risk list in `extension-api.md §7`. Amendment D is currently validated **on paper only** —
two TypeScript extensions were read and judged portable. This packet is the first chance to prove it
in C#, and the acceptance criteria below ask for it.

If some member cannot be made overridable without distorting the port, **say so in the PR**. That is
a finding about D1, not a detail.

### 2. `wordWrapLine` takes pre-segmented grapheme data

```ts
export function wordWrapLine(line: string, maxWidth: number, preSegmented?: Intl.SegmentData[]): TextChunk[]
```

It is exported, so it is surface, and the optional third parameter is a caching optimisation: callers
that already segmented the line pass the result rather than re-segmenting. `Intl.SegmentData` has no
C# equivalent, but T5.4 ported the segmenters — `getGraphemeSegmenter`, `getWordSegmenter` — and
`editor.ts` imports them from `utils.ts`. **Use the ported ones.** Do not re-implement segmentation,
and do not silently drop the optional parameter: the tests that exercise CJK and emoji wrapping are
the reason it exists.

### 3. `Editor` implements two interfaces

`export class Editor implements Component, Focusable`. Both are ported (`IComponent` gained its full
four members in T5.2b). Keep both, and note that `IComponent`'s optional members arrive as default
interface implementations — an override in `Editor` is a real override, not a shadow.

### 4. Null and empty are different in the autocomplete path

`editor.ts` consumes `AutocompleteProvider` and `AutocompleteSuggestions` from T5.6, where
`GetSuggestions` returns **null** when there is nothing to suggest, distinct from an empty item list.
`translation-patterns.md §1` applies, and the editor is where the distinction becomes visible — a
null suggestion set closes the popup, an empty one does not necessarily.

### 5. 185 cases is the largest suite in the project — do not batch-skip

The skip budget is a gate, not a release valve. If a case cannot be ported, it needs a row in
`.skip-budget.md` saying why and what clears it, and the PR must name it. Names preserved verbatim,
as always: a renamed case cannot be diffed against upstream later.

### 6. `Pi.Tui.Tests` runs serially, deliberately

`TestAssembly.cs` carries `[assembly: Parallelization(Mode = ParallelMode.None)]` with the reason
written above it. **Do not remove it** — two tests mutate process-global environment variables that
other classes read while constructing a TUI.

Where a test must observe asynchronous work, wait on the **condition**: use
`MemoryTerminal.WaitForRenderAsync`, which is settle-based, or `WaitForConditionAsync`. Two flakes
have already shipped into this package from fixed delays. A delay that is itself the behaviour under
test is the one exception, and it should say so in a comment.

### 7. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`.
- **Where a hazard here contradicts the TypeScript source, the source wins** — and **say so in the PR**.
