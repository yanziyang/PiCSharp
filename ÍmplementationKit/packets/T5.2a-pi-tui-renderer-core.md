# T5.2a — Pi TUI bounded writer and differential renderer core

## Objective

Port the renderer-owned part of `@earendil-works/pi-tui` so a sequence of rendered terminal
lines can be written incrementally without repainting unchanged content. This is the first slice of
T5.2; terminal device setup, alternate-screen lifecycle, image placement, and editor input remain
separate milestones.

## Specification

The TypeScript files below are read-only and are the behavioral specification:

- `reference/pi/packages/tui/src/tui-main-screen.ts` — bounded writes and main-screen differential
  rendering state machine
- `reference/pi/packages/tui/src/tui.ts` — cursor-marker extraction and cursor visibility behavior
- `reference/pi/packages/tui/src/terminal.ts` — terminal output escape sequences used by the writer
- `docs/tui-strategy.md` — golden-buffer and incremental-redraw gates
- `docs/translation-patterns.md` — C# translation rules

## Required behavior

1. `TerminalOutputWriter` buffers output in 1 MiB chunks, flushes full chunks immediately, preserves
   UTF-16 surrogate pairs at chunk boundaries, exposes the total character count, and writes no
   empty chunks.
2. `DifferentialRenderer` accepts a line buffer and terminal dimensions through a testable write
   delegate. It must:
   - emit synchronized-output markers (`CSI ? 2026 h/l`);
   - perform an initial render without clearing the caller's main screen;
   - perform a clear/full redraw after a forced redraw or width change;
   - compare old and new lines and repaint only the changed range when the range is visible;
   - clear stale rows when content shrinks;
   - maintain viewport and hardware-cursor row state across scrollback updates;
   - extract and remove `TuiConstants.CursorMarker` before writing, then position and show/hide the
     hardware cursor consistently with the TypeScript implementation;
   - expose immutable render metadata sufficient for tests and later TUI lifecycle code.
3. ANSI styling is preserved byte-for-byte. Grapheme width, ANSI reset insertion, Kitty/iTerm image
   handling, overlays, and alternate-screen behavior are deferred to their packets; this renderer
   must not strip or reinterpret ordinary escape sequences.
4. No terminal device or process-global state is accessed by the differential renderer. A later
   terminal adapter owns stdin/raw mode, resize events, and capability negotiation.

## Tests

Port the relevant upstream main-screen tests and add deterministic coverage for:

- exact first/full/differential output sequences;
- one-line edits producing a bounded incremental write rather than a full repaint;
- width-change full redraw and stale-line clearing;
- cursor marker extraction, removal, and hardware cursor visibility;
- chunk boundaries, including a surrogate pair split at the 1 MiB boundary;
- no-op frames updating only cursor state.

Use a fake write sink; never write to a real terminal.
