**Wave:** 2  **Delegation fit:** B  **Depends on:** `T2.1a`, `T2.2a`, `T1.3`

## Objective

Port the provider registry, dynamic model refresh lifecycle, auth application, provider dispatch,
deferred operations, lazy stream setup, and pure model/cost/thinking helpers from Pi's `models.ts`
and its directly required model-store/lazy-stream modules.

## Deliberate translations

- The TypeScript `Provider` interface is a C# service class backed by explicit delegates; the
  factory supplies a single `ProviderStreams` implementation or a map keyed by API identifier.
- JavaScript `undefined` versus explicit `null` in a model publication is represented by an
  explicit persistence-intent flag so a provider can distinguish “leave storage unchanged” from
  “delete the stored catalog”.
- `AbortSignal` races are implemented with linked cancellation tokens and `Task.WaitAsync`; an
  abandoned non-cooperative provider operation continues in the background while its late
  publication is rejected by the refresh generation check.
- TypeScript generic narrowing from `hasApi()` cannot be expressed at runtime in C#; the helper
  returns the same boolean predicate and callers retain the statically open `Model` contract.
- `Models` stream methods remain synchronous and return a lazy `AssistantMessageEventStream`; auth,
  provider selection, and setup failures are delivered as the upstream terminal error message.

## Oracle and acceptance

- Port the non-network `models-runtime.test.ts` cases covering provider CRUD, model lookup,
  dynamic refresh/cache restore, generation supersession, auth precedence/refresh, request option
  merging, lazy errors, streams, deferred capability errors, and pure cost behavior.
- Use only in-memory stores and deterministic fake providers; do not call real provider APIs.
- Build with zero warnings, run the full test executable suite, and pass format verification.
- Record any lifecycle behavior that cannot be reproduced exactly in the implementation summary.
