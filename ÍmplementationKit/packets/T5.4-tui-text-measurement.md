# `T5.4` — Port the TUI text-measurement layer

**Wave:** 5 (`Pi.Tui`)  **Delegation fit:** B
**Depends on:** nothing — `Pi.Tui` has no internal dependencies
**Plan reference:** `work-breakdown.md` wave 5, T5.4

---

## Why this goes first in wave 5

`Pi.Tui` is 10% implemented: layout and a differential renderer, 1,723 lines. Both are built on this:

```csharp
internal static int VisibleWidth(string line) =>
    line.Replace(TuiConstants.CursorMarker, string.Empty, StringComparison.Ordinal).Length;
```

That is `string.Length` — UTF-16 code units. It does not strip ANSI escape sequences, does not
segment graphemes, and does not know East-Asian width. `Pi.Tui` contains **no** use of `StringInfo`,
`Rune` or `TextElement`, and no ANSI awareness outside the escape constants the renderer emits.

So every layout decision and every differential-render diff already made in this project rests on a
placeholder. Nothing above it can be trusted until this lands, which is why it precedes the editor
(T5.3), images (T5.5) and the rest of wave 5.

Upstream states the consequence directly, in
`test/regression-regional-indicator-width.test.ts`:

> During streaming, "🇨🇳" often appears as an intermediate "🇨" first. If "🇨" is measured as width 1
> while the terminal renders it as width 2, differential rendering can drift and leave stale
> characters on screen.

## Objective

Port the text-measurement layer, then **rewire the existing `Pi.Tui` code to use it**.

## Hazards

### 1. Replacing the placeholder will change existing behaviour — that is the point

`LineLayout.VisibleWidth` in `StackLayout.cs` is called from `Layout.cs`, `LayoutComponents.cs` and
`DifferentialRenderer.cs`. Replacing it with a correct implementation **may break some of the 20
existing `Pi.Tui` tests**.

If that happens, it is a **finding, not a regression**: those tests were written against a naive
width model. Report each one in the PR with the old behaviour, the new behaviour, and which upstream
rule decides it. Fix the test to match upstream, not the implementation to match the test.

Do not leave two width functions in the codebase. The placeholder goes.

### 2. .NET gives you half of this for free — and only half

`docs/tui-strategy.md` records that `System.Globalization.StringInfo` and `System.Text.Rune` cover
grapheme clusters natively, which is genuinely easier than upstream's `Intl.Segmenter` shim.

**East-Asian width is the half you must supply.** Upstream uses the `get-east-asian-width` package.
`docs/dependencies.md §4` requires porting the data table rather than taking a dependency:
target `src/Pi.Tui/Text/EastAsianWidth.cs`. It is pure Unicode data, so correctness is testable
against the same source.

`InvariantGlobalization` is already `false` in `Directory.Build.props` for exactly this reason
(`solution-layout.md §4`). Do not change it.

### 3. The regression tests are the highest-value cases in the packet

`regression-regional-indicator-width` and `regression-overlay-cjk-boundary` encode bugs upstream
already found and fixed. Porting them is most of why this packet exists. A partial regional-indicator
flag must measure as width 2, not 1.

Cover, at minimum: CJK wide characters, combining marks (width 0), ZWJ emoji sequences, regional
indicator pairs *and* singletons, tabs, and ANSI-styled text where the codes contribute zero width.

### 4. ANSI must not count toward width

The current implementation counts escape sequences as visible characters. Since essentially all of
Pi's output is styled, this mis-measures nearly every real line. `visibleWidth`,
`truncateToWidth`, `sliceByColumn` and `wrapTextWithAnsi` must all treat SGR sequences as zero-width
while preserving them in output — truncating a styled line must not strip the styling of what remains.

OSC8 hyperlinks (`getOsc8LinkAtColumn`) have their own rules; port them as upstream has them.

### 5. Standing rules

- **`undefined` is not `null`** — `translation-patterns.md §1`.
- **Where a hazard here contradicts the TypeScript source, the source wins.** This has now happened
  twice — H1's `[JsonExtensionData]` and H3's `YamlDotNet` were both wrong and both correctly
  overridden. **Both times silently, found only by diffing.** If you override anything here, say so
  in the PR. That is what `AGENTS.md` requires and it is how these packets get corrected.
