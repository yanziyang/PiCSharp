# T3.5 — Port Google Generative AI and shared Gemini conversion

## Objective

Port the pinned upstream Google Generative AI stream adapter and the shared Gemini/Vertex
message, tool, thinking, and finish-reason conversion used by `@earendil-works/pi-ai`.
The adapter must use the Gemini `streamGenerateContent?alt=sse` wire protocol directly so the
shipping product has no Node.js or Google JavaScript SDK dependency.

## Required behavior

- Preserve the `GoogleOptions` surface as a C# provider-options type with auto/manual thinking
  configuration, `auto`/`none`/`any` tool choice, common request callbacks, cancellation, and
  retry options.
- Emit Gemini `contents`, `systemInstruction`, `generationConfig`, `tools`, `toolConfig`, and
  `thinkingConfig` with the exact upstream field names and omission rules.
- Send API keys as the Gemini `key` query parameter, merge model and request headers with the Pi
  user agent, and reject custom fetch injection with the upstream message.
- Parse Google SSE chunks in order. Preserve response IDs, text/thinking block transitions,
  thought signatures, function calls, raw finish reasons, tool-use promotion, usage including
  cached and reasoning tokens, and provider cost calculation.
- Implement model-specific thinking level/budget mapping for Gemini 2.5, Gemini 3, Gemini Flash,
  and Gemma 4, including the documented thinking-disabled configurations.
- Implement the shared converter rules: image placeholders for non-vision models, same-model
  thinking/signature replay only, valid base64 thought-signature filtering, Gemini 3 tool-call
  IDs, merged consecutive function responses, older-model image routing, strict-schema
  conversion, and synthetic results for orphaned tool calls.
- Use `JsonParseUtilities`/`System.Text.Json.Nodes`; do not add a dependency.
